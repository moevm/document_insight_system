# История изменений

Здесь описаны изменения поведения, развёртывания и настройки Document Insight System.
Версия приложения задаётся в `package.json`; соответствующий релизный тег — `v<версия>`.
История старых релизов в этом документе не реконструируется.

## Unreleased

- В общем `DecimalPlacesCheck` для отчётов и презентаций исключены URL http/https,
  DOI и номера ГОСТ. Сохранён алгоритм `pre-release`: знак числа, длинная целая
  часть и смешанные разделители; числа, слитые с буквами, не распознаются отдельно.
  Добавлены проверки совместной обработки исключений и обычных чисел.

- Добавлен `report_3_level_in_content_check`: поиск слишком глубокой нумерации
  в содержании отчёта; по умолчанию запрещён третий уровень и глубже.
- Удалены неиспользуемый прямой разборщик ODP и его утилиты. ODP по-прежнему
  обрабатывается через конвертацию в PPTX. Удалены старый frontend-файл,
  метаданные macOS, прототип Markdown-разборщика, неиспользуемый таймер, временный файловый helper и функция
  удаления устаревшей БД. Рабочие миграции и регрессионные тесты сохранены.
- Исправлено отображение допустимой глубины в сообщении критерия содержания;
  параметризованные тесты глубины теперь действительно собираются pytest.
- Удалены функции БД без вызовов и старый неиспользуемый разбор критериев
  LTI launch с его INI-конфигурацией. Текущие LTI custom-параметры сохранены.
- Локальные материалы ревью и операторские скрипты исключены из Docker-контекста.
- Обновлены инструкции разборщиков, LanguageTool, Ruff и финализации проекта.

- Объединены изменения `main`: исправлена проверка доступа администратора к маршрутам
  пользователей (401 без входа, 403 для пользователя без прав), обновлены ссылки LMS
  и адрес поддержки на домен `moevm.pro`.
- Selenium запускается на pull request. Сохранены актуальные Docker-сборки и проверки
  `pre-release`; старый дублирующий CI с образом 0.6 и JSON-файлом версии не используется.
- Добавлены регрессионные проверки доступа к списку пользователей для гостя,
  обычного пользователя и администратора.

## 3.0.0 — подготовка релиза, 2026-10-16

Изменения подготовлены локально. Эта запись не означает публикацию тега, образов
или GitHub Release. Версия 3.0.0 выделяет изменения оценки документов и развёртывания,
которые требуют проверки существующих настроек перед обновлением.

### Критерии и итоговая оценка

- Ошибки настройки больше не скрываются: неизвестный ID, неверная запись и ошибка
  конструктора дают видимый обязательный результат с нулевой оценкой.
- Эквивалентные записи, включая `["id"]` и `["id", {}]`, учитываются один раз.
  Один ID с разными параметрами сохраняется как несколько проверок.
- Исправлена обработка некорректного ответа критерия. Ноль обязательного критерия
  обнуляет набор, рекомендации исключаются из среднего.
- Добавлен `headers_references_check`. У `report_section_component` проверяется жирность
  компонентов, в том числе в нескольких runs и Markdown; `check_bold=false` оставляет
  только проверку наличия. Доступны индивидуальные `bold_check_exceptions`.
- Добавлены настройки карт и названий разделов, явной темы и порогов сходства цели/задач.
  Полные параметры — в [справочнике](docs/criteria.md).

### Разбор документов

- Markdown использует реальное количество страниц PDF, без искусственного минимума.
  Исправлены путь PDF, обработка результата md2pdf, относительные изображения,
  таблицы, списки, жирное начертание и дерево разделов.
- Исправлены включительные границы страниц PDF и сохранение абсолютных номеров.
  Изображения учитываются на всех страницах.
- В DOCX учитываются прямые свойства абзаца и явно заданные `False`/`0`, выравнивание
  `start/end` и видимый текст content controls Word.
- Исправлены правила стилей LR и сравнение оформления подписей с шаблонами.

### Структура и содержание отчётов

- Исправлены порядок первых страниц, поиск отсутствующих Реферата/Abstract,
  расположение заголовков в начале страницы и проверка заполнения задания.
- Ссылки в заголовках, абзацы вложенных разделов и компоненты в одном абзаце
  обрабатываются корректнее. Подписи, листинги и таблицы Markdown исключены
  из подсчёта обычных текстовых абзацев.
- Проверки литературы учитывают явные лимиты, таблицы DOCX, диапазоны ссылок,
  ручную нумерацию, дубли и повторный запуск.
- Проверки рисунков и таблиц учитывают последний абзац, несколько номеров, регистр,
  сокращения, повторные подписи и полное отсутствие подписей при наличии объектов.
- Запретные слова считаются с повторениями и как словосочетания; дополнительные
  запретные источники не изменяют общий список класса.
- Исправлены распознавание дробной части длинных чисел и первого употребления
  аббревиатур. Бланки первых страниц исключены из оценки доли таблиц.

### SW, NLP и презентации

- SW-проверки корректно обрабатывают значения по умолчанию, собственные словари,
  отсутствующие разделы/задачи и вложенность. Один источник не учитывается многократно.
- NLTK-данные не скачиваются во время проверки. Обработка предложений и морфология
  имеют резервные пути без дополнительной загрузки корпуса.
- Сходство цели/задач с содержанием считается как среднее абсолютное лексическое
  сходство разделов, без нормирования на максимум; введение исключено из сравнения.
- В презентациях исправлены обработка пустых слайдов и слайдов с изображениями,
  нестандартного соотношения сторон, повторного запуска и строкового `key_slide`.
- Тема сравнивается с другими заголовками; слайд задач не сопоставляется сам с собой.
  Исправлены номера слайдов в замечаниях.
- Проверка Git-ссылок работает независимо от порядка критериев, добавляет HTTPS
  для ссылок без схемы, использует timeout и обрабатывает сетевые ошибки.
- Орфография MD проверяется с первой страницы до источников. Адрес LanguageTool
  можно задать через `LANGUAGETOOL_URL` в окружении worker.

### Docker, зависимости и версия

- npm-зависимости фиксируются `package-lock.json`, Python-зависимости, включая
  транзитивные, — `requirements.lock` с SHA-256. Сборка использует `npm ci`
  и `pip install --require-hashes` на Linux/Python 3.12.
- Web, worker и Flower запускаются как `app`, UID/GID `10001:10001`, без capabilities.
  Отдельный root init-сервис без сети подготавливает права `files` и `flower_data`.
- Запуск web/worker ожидает готовность MongoDB/Redis и завершение init-сервиса.
  Домашний каталог app доступен для LibreOffice и Celery Beat, исходники принадлежат root.
- Исправлены пути импорта миграций БД, получение журналов проверки и создание ZIP
  во временном каталоге.
- Единственный источник версии — `package.json.version`. Make синхронизирует поля
  npm lock и `IMAGE_VERSION` в существующем `.env`, затем передаёт версию в Docker.
- Теги образов, labels и `/version/` используют общие метаданные сборки: версию,
  commit, дату, ветку и состояние `clean`/`dirty`.
- Удалены промежуточные JSON-файлы версии и старый генератор. Локальный запуск
  читает версию из манифеста, Docker — из окружения образа.
- Добавлены проверка согласованности версии в CI, тесты синхронизации и скрипт
  проверки действующего развёртывания.

### Совместимость внешних систем

Контракт `POST /tasks/md` с `access_token` в multipart-форме сохранён: без `full_response`
возвращается строковый `check_id`, с непустым полем — JSON с `task_id`/`check_id`.
Сохранены опрос готовности, SVG и экспорт CSV/ZIP по токену. HTML, журналы и PDF
требуют авторизации, как и прежде; токен загрузки не заменяет сессию.

### Миграция развёртывания

1. Сохраните резервную копию MongoDB/GridFS, файловых volume и `.env`.
2. Сохраните `COMPOSE_PROJECT_NAME`, `ACCESS_TOKEN`, секреты и путь данных MongoDB.
3. Соберите новые образы, остановите старые web/worker/Flower, выполните `volumes-init`
   над существующими volume и пересоздайте сервисы через `up`.
4. Проверьте UID/GID, доступ к файлам и сквозной сценарий с обоими режимами API.

Команды приведены в [README](README.md#обновление-существующего-развёртывания).
Для миграции прав не удаляйте volume. Изменение `.env` не сбрасывает пароль
существующего администратора. При ручном Compose после изменения версии сначала
выполните `make sync-version`.

### Миграция существующих наборов

1. Проверьте ID и параметры: ошибки создания критерия теперь проваливают набор.
   Удалите случайные дубли; один ID с разными настройками допустим.
2. У `literature_references` явные `min_ref`/`max_ref` имеют приоритет. `null` выбирает
   значения карты, затем резервные 1/1000. Старый явно заданный лимит мог игнорироваться.
3. `short_sections_check` применяет оба минимума: `min_section_count` — число абзацев,
   `min_section_len` — число слов во всём разделе с подразделами, а не в одном абзаце.
4. `needed_headers_check` по умолчанию использует `heading 2` для VKR и `heading 3`
   для LR. Для НИР/практики настройте карту заголовков и первые страницы отдельно:
   один `report_type="VKR"` не выбирает требования другого шаблона.
5. Для MD исключите проверки геометрии и оформления DOCX. При необходимости отключите
   требование жирности компонентов через `check_bold=false` или задайте исключения.
6. `sw_tasks_check` требует раздел «Задачи». Остальные SW-проверки не считают
   отсутствующий настроенный раздел успешным. `sections_info=null` выбирает
   `SW_KEY_QUESTIONS_SECTIONS`; неизвестный ключ — ошибка настройки.
7. Пустые карты SW и пустые правила соответствующих словарных проверок становятся
   рекомендациями, не добавляя успешный балл в среднее. Карты размера
   `SW_ANALOGS_SECTIONS` и `SW_FINAL_SECTIONS` пусты; задайте собственные лимиты.
   Лимиты `sw_sections_size_check` — верхние границы.
8. `style_check` и `lr_sections_check` оставлены для совместимости как deprecated.
   Для новых наборов используйте актуальные проверки структуры и оформления.
9. Сравните оценки на представительных работах: исправленные проверки могут снизить
   балл за ранее пропускавшиеся нарушения. Особого внимания требуют сходство текстов,
   длина разделов, запретные словосочетания и тема.

### Проверка и её границы

- Тестовые Markdown/DOCX/PDF-файлы в `tests/fixtures/reports` исключены из общих
  правил игнорирования; перед релизом они должны быть добавлены в Git.
- В CI добавлены запуск критериев и разборщиков из чистой копии с зависимостями из lock,
  проверка HTTP-ошибок web/Flower и сквозной сценарий загрузки с `access_token`.
- Нормализован `FLOWER_PREFIX`: `/` открывает корень панели, `/flower/` — вложенный
  адрес, без двойных слешей в маршрутах.
- Скрипт ожидания Selenium находит и уже завершившийся контейнер, проверяя его exit code.
  Локальный restart использует Compose v2 и общие Make-цели сборки/запуска.


При подготовке изменений прошли 118 тестов критериев/отчётов и 7 тестов синхронизации
версий. Повторный прогон прошёл в чистой копии кандидата и внутри свежего worker-образа
с зависимостями из lock. Selenium: 14 успешных сценариев и один пропуск по типу набора;
презентация отдельно прошла HTTP-пайплайн с 24 записями базового набора без внутренних ошибок.
Проверены корень и вложенный префикс Flower, static-ресурсы и Basic Auth. В локальном Docker проверены реальная конвертация DOCX и MD, выполнение
31 базового критерия без внутренних исключений, HTML/SVG/PDF, журналы, CSV/ZIP,
оба режима API и отказ с неверным токеном. Проверены работа без root, доступ
к существующим файлам и сохранность их содержимого после миграции прав.

Это проверка конкретных сценариев, а не гарантия для любого документа. Тесты критериев
подменяют внешние сервисы; сквозной сценарий не проверяет LTI passback. Оценки «воды»,
сходства, аббревиатур, подписей презентации и доли таблиц остаются эвристическими.
Команды воспроизведения и побочные эффекты сквозного сценария — в
[README](README.md#разработка-и-проверки).
