# История изменений

Версия приложения — `package.json.version`; релизный тег — `v<версия>`.

## Unreleased

- Таблицы пользователей, статистики, журналов, критериев, наборов и результатов
  используют общий компонент: поиск, фильтры, сортировка, страницы, выбор столбцов
  и сохранение состояния в URL. В карточке пользователя отображаются его проверки.
- Добавлены фильтры роли, способа входа и состояния проверки. Исправлены сортировка
  столбцов, пагинация последних проверок и включение последнего дня диапазона дат.
  Текстовые фильтры ищут подстроки без регулярных выражений; числовые поддерживают
  точные значения, диапазоны и сравнения. Экспорт учитывает текущие фильтры.
- Администратор может вручную назначать и снимать права в карточке пользователя.
  Роль видна в списке; следующий LTI-вход обновляет её из LMS.
- При каждом LTI-входе роль существующего пользователя синхронизируется с LMS:
  `Instructor` даёт права администратора, отсутствие этой роли снимает их.
  Учитываются все роли в списке, независимо от порядка.
- НИР1/2/3 допускают структурные, нумерованные и вложенные заголовки ВКР
  с сохранением собственных обязательных разделов.
- Общие названия и шаблоны разделов собраны в `section_patterns.py`, включая
  варианты «использованной литературы» для DOCX.
- Поиск ссылок и объектов DOCX ограничен фактическим разделом литературы.
  Упоминания в тексте и строки содержания не считаются заголовками разделов.
- `right_words_check` читает абзацы и таблицы DOCX, исключает содержание
  и пересчитывает результат при повторном вызове.
- SWTask2/3 требуют h2 «Описание предметной области» / «Описание метода решения».
  Доступны фиксированные карты `SWTask2_HEADERS` / `SWTask3_HEADERS`.
  Изменения `OPNP_HEADERS` применяются и к сохранённым наборам с этой картой.
- `DecimalPlacesCheck` исключает URL, DOI и номера ГОСТ; учитывает знак,
  длинную целую часть и смешанные разделители. Числа внутри слов не выделяются.
- Добавлен `report_3_level_in_content_check` с настройкой запрещённой глубины.
- Исправлен доступ к управлению пользователями: 401 без входа, 403 без прав.
  Ссылки LMS и поддержки используют домен `moevm.pro`.
- Удалены неиспользуемые функции БД/LTI, альтернативные алгоритмы разборщиков
  и критериев, закомментированный код PDF-разбора, прямой разборщик ODP
  и вспомогательные прототипы. ODP обрабатывается через PPTX.
- Сокращены README и история изменений; команды запуска и API описаны в README.
- Локальные материалы исключены из Docker-контекста; Selenium запускается на PR.

## 3.0.0

### Обработка и оценка

- Ошибки конфигурации критериев дают обязательный нулевой результат.
  Эквивалентные записи дедуплицируются; один ID с разными параметрами сохраняется.
- Ноль обязательного критерия обнуляет набор, рекомендации исключаются из среднего.
- Добавлен `headers_references_check`, настройки компонентов разделов,
  карт заголовков, темы и порогов сходства цели/задач.
- Исправлены разбор Markdown, включительные диапазоны страниц PDF,
  наследование стилей DOCX и текст content controls Word.
- Исправлены проверки первых страниц, литературы, ссылок, подписей,
  аббревиатур, структуры SW и пустых слайдов.
- Текстовые проверки имеют резервные пути без скачивания NLTK во время обработки.
  Git-ссылки проверяются с timeout; адрес LanguageTool задаётся в окружении worker.

### Развёртывание

- Зависимости закреплены в `package-lock.json` и `requirements.lock` с SHA-256.
- Web, worker и Flower работают как `app` (`10001:10001`) без capabilities.
  `volumes-init` подготавливает права общих volume без изменения содержимого файлов.
- Запуск ожидает MongoDB/Redis и подготовку volume; миграция выполняется перед web.
- Версия берётся из `package.json`, синхронизируется с npm lock и локальным
  `IMAGE_VERSION`. Метаданные образов доступны на `/version/`.
- Исправлены журналы, создание ZIP, префикс Flower и ожидание Selenium.

### Совместимость API

`POST /tasks/md` принимает `access_token` в multipart-форме. По умолчанию ответ —
строка `check_id`, при непустом `full_response` — JSON с `task_id`/`check_id`.
HTML, журналы и PDF требуют сессии; экспорт CSV/ZIP принимает токен в query.

### Миграция существующих наборов

- Проверьте ID и параметры: ошибка конструктора проваливает набор.
- У `literature_references` явные `min_ref`/`max_ref` имеют приоритет над картой.
  `null` выбирает значения карты, затем резервные 1/1000.
- `short_sections_check` проверяет минимум абзацев и суммарное число слов
  раздела с подразделами.
- `needed_headers_check` использует Heading 2 для VKR, Heading 3 для LR.
  Для НИР/практики нужны явные карты и настройки первых страниц.
- Исключите проверки оформления Word из MD-наборов; при необходимости задайте
  `check_bold=false` или исключения жирности компонентов.
- `sw_tasks_check` требует раздел «Задачи»; отсутствующий настроенный раздел
  проваливает SW-проверки. Пустые словарные правила становятся рекомендациями.
  Пустые карты размера требуют собственных лимитов.
- `style_check` и `lr_sections_check` имеют статус deprecated, но доступны
  сохранённым наборам. Новые наборы должны использовать отдельные проверки
  структуры и оформления.
- Сравните оценки на работах курса: изменения алгоритмов могут менять баллы.
