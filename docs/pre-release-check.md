# Предрелизная проверка — 2026-10-23

Проверена версия 3.0.0 в ветке `pre-release`: база `d815b88e` и изменения
финализации из этого коммита. Номер приложения и зависимости не менялись.

## Результаты

- Критерии и разборщики: 148 тестов прошли. Внешние сервисы в них подменяются.
- Версии: 7 тестов `scripts/test_versioning.py` и `make check-version` прошли.
- `npm ci` и `npm run build` прошли; Webpack выдал 3 предупреждения о размере bundles.
- `make build-all` и повторная сборка окончательных web/worker через `make build` прошли.
- Ruff и форматирование кода проекта прошли. Полный `ruff check .` в рабочем
  каталоге дополнительно видит E501 в локальном незакоммиченном `run_recheck.py`;
  этот пользовательский скрипт не изменялся и не включён в коммит.
- `git diff --check`, локальные ссылки Markdown и наличие всех 63 ID в справочнике проверены.
- Реальный `scripts/verify_deployment.py` прошёл: DOCX, два режима Markdown API,
  Celery, GridFS, исходники, PDF, результаты HTML/SVG, журналы, CSV/ZIP и отказ
  с отсутствующим/неверным токеном. Созданы три синтетические проверки в отдельной БД.
- Selenium: основной набор — 14 успешных сценариев и 1 пропуск по типу набора;
  пропущенная загрузка PPTX отдельно прошла с презентационным набором.
- Flower с авторизацией и LanguageTool ru-RU вернули HTTP 200.
- Web и worker: UID/GID `10001:10001`, общий каталог доступен на чтение и запись.
  После остановки писателей и повторного `volumes-init` заранее созданный
  синтетический файл сохранил содержимое и остался доступен пользователю app.

## Границы проверки

Стенд использовал отдельный Compose-проект `dis-finalization`, отдельный volume
MongoDB и порты 18080/15555. Пользовательская БД и документы не затрагивались.
Образы помечены `dirty`: в рабочем каталоге сохранены пользовательские скрипты
и материалы ревью. Они исключены из Docker-контекста и итогового коммита.

LTI passback в LMS и миграция копии старой пользовательской БД не проверялись.
Известные направления дальнейшей работы остаются в [плане](ROADMAP.md).
Эта проверка не означает публикацию релиза, тегов или образов.
